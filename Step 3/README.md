# 🛒 דוח פרויקט: ניהול רשת "רמי לוי" - שלב ג'  
##  אינטגרציה ומבטים 統合


בשלב זה ביצענו אינטגרציה בין מערכת ניהול רשת החנויות (רמי לוי) לבין מערכת חיצונית שהתקבלה כגיבוי. התהליך כלל הנדוס לאחור, איחוד סכמות ושימוש ב-Views.

---

## 1. ניתוח המערכת החדשה (Reverse Engineering)
לאחר קבלת הגיבוי מהצוות המקביל, ביצענו תהליך של הנדוס לאחור כדי להבין את המבנה הלוגי של בסיס הנתונים.

### אלגוריתם הנדוס לאחור שיושם:
1. **מיפוי טבלאות לישויות:** כל טבלה בגיבוי הופכת לישות ב-ERD החדש.
2. **חילוץ תכונות:** העמודות בכל טבלה הוגדרו כתכונות (Attributes), תוך זיהוי מפתחות ראשיים (PK) כבסיס לזיהוי הישות.
3. **זיהוי קשרים (Relationships):**
   - קשר **1:N**: זוהה על ידי מפתחות זרים (FK) בטבלאות.
   - קשר **N:M**: זוהה בטבלאות המורכבות ממפתחות זרים בלבד (טבלאות קשר).
4. **קביעת אילוצים:** הגדרת חובת השתתפות לפי אילוצי `NOT NULL`.

---

## 2. תהליך האינטגרציה
בשלב זה חיברנו את המערכת המקורית שלנו עם המערכת החדשה ליצירת בסיס נתונים אחד אחוד.

### החלטות עיצוב ואינטגרציה:
* **נקודת החיבור:** החלטנו לקשר בין [שם ישות ממערכת א'] לבין [שם ישות ממערכת ב'] כדי לאפשר זרימת מידע בין האגפים.
* **טיפול בכפילויות:** (לדוגמה: איחוד טבלאות משתמשים או התאמת סוגי נתונים).
* **שינויים בסכמה:** ביצוע שינויים באמצעות פקודות `ALTER TABLE` מבלי למחוק את הנתונים הקיימים.

---

## 3. מבטים (Views)
יצרנו 3 מבטים מורכבים המאפשרים שליפת נתונים רלוונטיים מהמערכת המאוחדת:

| שם המבט | תיאור | אגף |
| :--- | :--- | :--- |
| `View_Original_Dept` | מבט המציג נתונים מהאגף המקורי (רשת החנויות) | מקורי |
| `View_New_Dept` | מבט המציג נתונים מהאגף שהתקבל | חדש |
| `View_Integrated` | מבט משולב המצליב נתונים בין שני האגפים | משולב |

---

## 4. תוצרי השלב בתיקייה
הקבצים הבאים זמינים בתיקיית "שלב ג":
* `DSD_New.png` - תרשים לוגי של האגף החדש.
* `ERD_New.png` - תרשים ישויות קשר של האגף החדש.
* `ERD_Combined.png` - התרשים המאוחד.
* `Integrate.sql` - פקודות SQL לשינוי הטבלאות (DDL).
* `Views.sql` - יצירת המבטים והשאילתות עליהם.
* `backup3.sql` - גיבוי מלא של בסיס הנתונים המאוחד כולל נתונים.
